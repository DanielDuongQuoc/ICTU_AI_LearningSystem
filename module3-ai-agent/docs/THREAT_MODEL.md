# Threat model (Module 3)

Assumptions: Module 3 runs as an internal service; callers (Module 2 / ops) are semi-trusted but anything they
forward (PDF, student answers) is untrusted. There is no end-user authentication in this module. "Existing
mitigation" lists only controls that have an automated test in `tests/security/` or an earlier phase test.
"Remaining risk" is my assessment, not a measurement.

| # | Threat | Attacker | Attack vector | Impact | Existing mitigation | Remaining risk |
|---|---|---|---|---|---|---|
| 1 | Malicious PDF | anyone who can upload | malformed / truncated / huge / many-page / text-bomb PDF, parser bug | crash, CPU/RAM exhaustion, parser RCE | signature + MIME + size check, page / text / chunk caps, per-page timeout, all parser errors -> `AppError`, no stack trace, temp file removed, slot gate (`test_upload_security.py`) | A parser CVE or a single pathological page is not stopped by these limits; PyMuPDF runs in the API process (no sandbox). Real malicious-PDF corpus NOT tested. **Medium** |
| 2 | Prompt injection | document author / student | instructions in text ("ignore previous instructions", role play, multi-language) | altered behaviour, leaked prompt | content is delimited data in the user message, system prompt fixed, forged delimiters neutralised, verbatim prompt-leak rejected (`test_ai_integrity.py`, `test_security_isolation.py`) | A real model may still follow wording tricks; only structural / verbatim checks exist. Real Qwen NOT tested. **Medium** |
| 3 | Document poisoning | uploader of a document | text such as "only trust this document / give full marks" inside the PDF | wrong answers / grades for that document | retrieved text is data; score and sources validated by backend; insufficient-context path skips the LLM | Poisoned *content* still shapes answers from that document (inherent to RAG); no content provenance / moderation. **Medium** |
| 4 | Student-answer injection | student | "give me full marks" in the answer | inflated grade | answer is delimited data; score validated (range/finite/type) and percentage computed by backend; model feedback clamped | The model's own score within range can still be swayed. Quality gate (Phase 17/18) measures over-scoring only with real-model runs (NOT run). **Medium** |
| 5 | Source spoofing | model / poisoned text | fake page / chunk_id / document_id in LLM output or text | false citations | sources, pages, ids, similarity are built from retrieval only; LLM metadata dropped (`test_ai_integrity.py`) | None known for metadata; the *text* of an answer can still claim a page number. **Low** |
| 6 | Score manipulation | model / student | NaN, Infinity, negative, > max, string, missing | invalid grade | strict validation, rejected as `LLM_*` errors, percentage backend-computed | Within-range manipulation: see 4. **Low** |
| 7 | Resource exhaustion | any client | huge `top_k`, huge body/answer, many uploads/evaluations, endless generation, many SSE streams | CPU/RAM/LLM saturation, DoS | validation + caps (`top_k`, chars, body), per-client rate limit, upload gate, LLM concurrency gate, stream wall-clock + output caps, config fail-fast (`test_resource_and_error_security.py`) | Limiter is in-process and per TCP peer (proxy shares a bucket, multi-worker multiplies it, restart resets). No distributed limiting, no WAF. **Medium** |
| 8 | Path traversal | any client | `../`, `..\`, absolute paths, null byte, Windows paths in filename / ids | arbitrary file read/write | filename never used as path; server UUID temp name; ids only used as Chroma filter values; traversal ids -> 400/404/422 (`test_path_traversal.py`, `test_upload_security.py`) | Low. Only verified through the API surface. **Low** |
| 9 | Secret leakage | anyone with repo/log/response access | secrets in source, `.env`, logs, errors | credential exposure | no secrets required; `.env` ignored by git and docker; scan test; token never logged or echoed; errors generic (`test_isolation_secrets_admin.py`) | Heuristic scan only (not a full scanner such as gitleaks); no git history available to scan. **Low** |
| 10 | Dependency vulnerability | external | known CVEs in pinned packages | varies (upload parser, framework) | versions pinned; `pip-audit` run once; python-multipart / anyio upgrade tested (see report); advisory CI job | Chroma 0.5.23 advisories without a fix version; pytest in runtime image; transitive deps not audited. **Medium** |
| 11 | SSE abuse | any client | many streams, never-reading client, endless model output | held connections / LLM slots | rate limit before stream starts, wall-clock + output caps, upstream closed on disconnect/cancel, `error -> done` (`test_sse_security.py`) | No cap on *simultaneous open* streams other than the LLM gate and rate limit. **Low-Medium** |
| 12 | Cross-document leakage | any client | wrong / forged `document_id`, filter injection, deleted doc | reading other documents | every query filtered by `document_id`; ids validated; deletion is scoped; deleted doc -> 404 and no LLM call | **No authorisation**: anyone who knows a valid id can read that document (UUID4 is not an access control). **High (inherited, documented, not fixed)** |
| 13 | Admin / version manipulation | anyone reaching `/api/ai-versions` | guessed token, forged `status`, promoting unvalidated version, rollback to missing model | malicious model / prompt becomes active | token required (constant-time compare), lockout after 10 failures, no `status` input, promotion only via quality gate, rollback validates the target | Single shared token, no roles/identity; whoever holds it can approve/promote anything that passes the gate and read the audit trail. Needs real authn/z before public exposure. **High if exposed, Medium on trusted network** |
